# Ternet Bytecode and TVM

## VM role

TVM executes compiler-generated bytecode. Source parsing is never performed by the runtime.

## Current bytecode

The current implementation has exactly two instructions:
- `PrintString`
- `Halt`

## V1 instruction families

Target families:
- constants
- local/global load/store
- arithmetic
- comparison
- boolean operations
- jumps
- calls/returns
- collection construction
- field access
- allocation
- pattern matching
- error propagation
- async task operations

The final numeric encoding is not frozen until verification and serialization are implemented.

## Verification

Production bytecode should validate:
- opcode values
- operand bounds
- jump targets
- stack discipline
- constant references
- function boundaries

## Future native backend

Ternet IR should remain independent from TVM bytecode so a future native backend can reuse semantic analysis and optimization.
